Aim

The aim of this project is to develop StayNearby, an AI-powered two-sided short-duration rental marketplace that connects property owners with guests needing flexible accommodations for a few hours, a half day, or a full day. The system overcomes the rigidity and latency of traditional hospitality platforms by providing an explainable four-stage machine learning recommendation pipeline, neighbourhood demand forecasting with uncertainty quantification, and an automated MLOps continuous monitoring infrastructure.

Dataset Used

The system utilizes a realistic multi-modal dataset specifically modeled after Chennai's urban residential and commercial micro-markets:

  • Property Listings Dataset: 21 verified seed properties across 8 key Chennai neighbourhoods (Guindy, Velachery, Adyar, T. Nagar, Anna Nagar, Mylapore, OMR, and Nungambakkam) featuring precise geospatial coordinates, tiered pricing structures (hourly, half-day, full-day), multi-category amenities, and verified guest capacities.
  • Renter Interaction Dataset: 5,000 synthetic guest search queries, impressions, click-through records, and booking events with realistic price-sensitivity distributions and time-of-day demand preferences.
  • Time-Series Neighbourhood Demand Dataset: 2,920 longitudinal observations covering four time slots per day (Morning, Afternoon, Evening, Night) over two years, incorporating seasonal and weekly cyclical demand patterns.

Techniques Used

Geospatial Distance Computation

The system implements the great-circle Haversine formula to compute geodesic distances between user search coordinates and property coordinates. Out-of-radius listings (beyond the user-specified threshold, default 15 km) are pruned before scoring.

Four-Stage Explainable Recommender

The recommendation pipeline operates through four progressive stages: (1) Hard eligibility filtering for active listings, capacity, and supported duration; (2) Geospatial proximity filtering and booking collision prevention; (3) Multi-factor weighted heuristic baseline computing Bayesian rating, distance decay, budget fit, and Jaccard amenity similarity; and (4) Supervised candidate re-ranking using a calibrated GradientBoostingClassifier.

Time-Slot Demand Forecasting

Neighbourhood demand is predicted using a HistGradientBoostingRegressor trained on lagged historical bookings (1-day, 2-day, 7-day lags), 3-day and 7-day rolling means, and calendar encodings. The model outputs a point prediction accompanied by a 95% confidence interval derived from residual variance.

Population Stability Index (PSI) Drift Monitoring

To ensure production stability, real-time feature distributions (travel distance, budget ratios) are continuously compared against baseline distributions using the Population Stability Index. Alerts are triggered when PSI exceeds 0.25.

MLOps and Deployment Techniques

The backend is architectured as a decoupled RESTful service using FastAPI. Machine learning experiments, metric logs (Precision@K, NDCG@K, MAE, RMSE), and hyperparameter runs are tracked persistently through a local MLflow SQLite registry. An atomic model registry manifest manages candidate model evaluation, validation gates, and instant rollback capabilities. Docker multi-stage containerization enables reproducible runtime deployment.

Methodology

Step 1: Ingest User Request and Resolve Geospatial Coordinates
The client transmits search parameters including desired neighbourhood/coordinates, duration type (hourly, half-day, full-day), budget constraint, guest count, and required amenities.

Step 2: Stage 1 Eligibility & Booking Collision Check
The backend queries properties filtered by active status and capacity. A subquery checks the bookings database to eliminate properties with overlapping confirmed reservations during the target window.

Step 3: Stage 2 Geospatial Distance Pruning
Geodesic Haversine distances are computed dynamically between target coordinates and property coordinates. Listings beyond the specified search radius are pruned.

Step 4: Stage 3 Multi-Factor Heuristic Attribution
Remaining candidates are scored across distance decay (30%), budget fit (25%), Bayesian rating (20%), amenity Jaccard similarity (15%), and prior user engagement (10%). Human-readable explanations are generated.

Step 5: Stage 4 Gradient Boosted Re-Ranking
Feature vectors are passed to the trained GradientBoostingClassifier. Calibrated probabilities re-rank top candidates while blending explainable feature tags.

Step 6: Neighbourhood Demand Forecasting & Variance Quantification
For host queries, the HistGradientBoostingRegressor predicts expected booking request volume across time slots and attaches a 95% confidence interval ($\hat{y} \pm 1.96 \cdot \text{RMSE}$).

Step 7: Real-Time PSI Drift Evaluation and Model Governance
Inference logs are evaluated against training reference distributions to ensure zero distribution drift. The model registry allows administrators to activate or roll back models with one click.

Step 8: Client Delivery & Address Privacy Shielding
The API returns structured results hiding the exact residential address until a booking is confirmed.

Output Expected

  • A ranked list of candidate properties personalized to user coordinates, budget, and duration type.
  • Transparent attribution tags accompanying each recommendation (e.g., "Within 2.1 km", "Within ₹500 budget").
  • Dynamic hourly and daily price calculations computed server-side with zero pricing discrepancies.
  • Host analytics visualization displaying predicted demand scores and booking volumes with 95% confidence bounds.
  • Administrative MLOps telemetry reporting active model versions, NDCG/MAE metrics, and feature PSI drift levels.

Conclusion

The StayNearby AI-Powered Short-Duration Home Rental Marketplace successfully implements an industrial-grade, full-stack rental platform specifically tailored for short-duration stays. By seamlessly integrating an explainable four-stage machine learning recommender, a neighbourhood time-slot demand predictor with residual uncertainty intervals, and continuous MLOps governance into a responsive web application, the system demonstrates that modern AI marketplace solutions can be both highly accurate and transparent.

The platform enforces strict privacy-by-design principles to protect host residential addresses while providing host dynamic pricing insights. With zero paid external dependencies and full local runnability, the application serves as a comprehensive, production-ready capstone project that meets all functional and architectural specifications.
